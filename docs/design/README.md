# 玩法设计

本目录保存系统的目标体验、已接受设计、候选方案与取舍理由。项目整体阶段见 [根 README](../../README.md)，具体任务进度与结果从 [工作索引](../../work/README.md) 进入。

## 项目方向

- 以《东方 Project》的器物、能力与世界设定提供设计素材，重点探索特色能源、加工机制和实用能力。
- 优先通过物品、工艺和交互表达题材，控制角色模型等美术制作的规模，使项目适合个人维护。
- 既有讨论倾向于让通用搬运与调度借助外部系统；是否集成特定模组、采用何种接口或增加必需前置，仍需具体任务决定。

## 如何理解设计记录

维护者提出的功能意向、已经接受的具体方案和代码已经实现的行为分别记录。功能意向可以先于技术方案存在；候选方案明确标为待定，AI 提议须经过采纳才能成为已接受设计。

系统文档只标明理解设计所需的实现边界，例如已支持哪些行为、哪些部分仍未实现。详细工作进度和测试证据链接到对应任务；更新时机遵循 [协作规则](../../AGENTS.md) 中的维护要求。

涉及原作事实的具体主张，应给出资料依据并区分二创延伸。
