# 飞行系统

本文维护飞行的功能意向、已确认约定、候选方案与实现边界。候选推荐不表示已经采纳或排定开发。参考实现、版本和固定源码链接见 [002 调研记录](../../work/002-flight-research/RESEARCH.md)，当前原型进度与验证证据见 [003 任务入口](../../work/003-flight-prototype/TASK.md)。

## 已提出的体验方向

希望在前期获得实用的飞行能力，并让两种题材表达具有不同用途：

| 功能意向 | 希望提供的体验 |
| --- | --- |
| 灵梦式飞行 | 偏向低速、精确的移动，辅助建造与细致操作 |
| 魔理沙式扫帚 | 偏向快速移动，服务跑图和长距离出行 |

这些名称表达题材与用途，具体获取方式和能力载体仍待决定；目前没有承诺首版同时实现两者。

## 已确认的共同操纵

2026-10-27，维护者确认 Shift 用于低速模式；2026-10-28，进一步确认两种飞行共享以下操作：

| 输入 | 已确认行为 |
| --- | --- |
| 视角 | 水平朝向决定移动输入的参照方向；抬头、低头不直接引发爬升或俯冲 |
| W / S | 相对于水平视角向前 / 向后平移 |
| A / D | 相对于水平视角向左 / 向右平移 |
| 空格 | 上升 |
| Shift | 低速模式 |

2026-10-28 后续确认：两种飞行保留常速与低速两档，不另设 Ctrl 加速。扫帚的 Ctrl 退出约定见下文。

下降由独立动作控制，当前默认候选见下节。转头会改变移动输入的参照方向，但不会单独产生推进；已有惯性如何消退或转向，由尚待确定的加速与制动规则处理。

这些约定确定了共同的操作语义及表中默认键位，不等于要求硬编码物理键。是否跟随原版跳跃、潜行动作的改键，Shift 按住还是切换、低速倍率及对升降速度的影响，仍需决定。统一操纵也不决定两种飞行必须采用相同的底层实现或能力载体。

空中使用扳手等工具的潜行交互仍是设计目标，需要与低速模式共同评估；它不等于已经兼容所有工具。

## 下降键候选与输入分工

2026-10-28，维护者同意以 **V 为下降默认候选、C 为备选**；这确定了比较顺序，尚未最终确定下降默认键。两种飞行共用下降动作。

| 候选 | 理由与待验证的负担 |
| --- | --- |
| V：当前默认候选 | 尝试由拇指在空格和 V 之间切换，让小指负责 Shift、其余手指保留 WASD；本项目对应原版没有默认绑定 V，但外部模组可能占用 |
| C：备选 | 如果拇指按 C 更自然，可以替代 V；原版创造模式的 C 配合数字键会保存快捷栏，需要考虑飞行中切换栏位的冲突 |

两键若由食指操作，都可能影响同时按 D。手型、键盘布局及握法不同，不能仅凭距离判断舒适度；应比较低速下降、下降中侧移，以及拇指在上升与下降之间切换的操作。上述舒适度判断尚未试玩，默认键位事实见调研记录中的本地源码补充。

**Ctrl 已确定用于下扫帚**，具体触发方式见退出约定。下降继续独立使用上述候选键，避免按住 Shift 低速下降时争用小指。Ctrl 默认关联原版疾跑，实现时需处理相应输入冲突，避免在已确认的两档之外隐含增加速度档位；此处不决定灵梦式飞行的关闭键。

## 方案取舍与手感候选

统一平移操作已成为当前设计，之前的转向比较据此收敛：

| 已比较方案 | 当前取舍及保留的参考价值 |
| --- | --- |
| A：Hexerei 式按键转向 | 原方案让 A/D 调整扫帚朝向，适合强调驾驶感，但不符合已确认的左右平移；不再列为当前并行候选。仍可参考其惯性、实体与乘客处理 |
| B1：EvilCraft 式完整视角推进 | 俯仰参与三维航向，看地面可能同时俯冲；不符合已确认的独立升降。仍可参考其运动平滑与物品、实体生命周期 |
| B2：水平视角与独立升降 | 已进一步明确为两种飞行共用的 WASD 平移；A/D 不再待选，也不依赖扫帚先转向再侧移。这是本项目的组合设计，不声称参考模组完整采用了它 |

取舍理由是减少两种飞行之间的操作切换，并允许观察地面或建筑顶部时独立控制高度。参考版本与源码事实仍保留在调研记录；这里的选择不表示已经验证实现或手感。

共同操纵下，两种飞行可通过速度、加速与制动区分用途，以下实现路线和具体手感仍为候选：

| 方面 | 灵梦式飞行 | 魔理沙式扫帚 |
| --- | --- | --- |
| 实现路线 | 候选沿用玩家自身的创造式飞行并调整操纵 | 候选采用可骑乘的独立实体；骑乘形式不要求车辆式转向 |
| 移动与停位 | 优先验证低速精度和及时停位；只减小移动输入不代表能立即停住 | 优先验证较高速度与适度的加速过程；惯性过大可能妨碍转向和降落 |
| 低速 | 候选优先比较按住 Shift、松开退出，切换式仍待比较；升降速度是否同步降低尚待定 | 遵守同一低速操作；低速时的制动与响应需单独调节，不能仅按比例缩小所有参数 |
| 表现 | 以玩家姿态与反馈表达状态，具体资源未定 | 可考虑转身、倾斜动画，但视觉平滑不应迫使侧移等待模型转身；不因此承诺具体美术方案 |

S 的操作语义已确定为后移；若保留惯性，反向输入可能先抵消前进速度再后移，具体响应仍需验证。是否另设专门刹车，不能通过重新把 S 定义成只能刹车来含混处理。持续按 W 时左右转头会改变输入方向，自由观察是否必要仍需讨论。

候选保留工具所需的潜行交互，同时进入低速，单独处理创造式飞行的下降逻辑；不能仅清空潜行输入来阻止下降。灵梦式飞行的启停仍可用原版双击跳跃作为对照，正式启停和落地行为尚未确定。

## 下扫帚与退出

### 已确认的按键与触发方向

2026-10-28，维护者确认：**Ctrl 用于下扫帚；有安全落点时短按，空中长按确认。** 该动作只在扫帚骑乘期间负责退出，Shift 继续用于低速，不能同时触发下扫帚。

| 情况 | 已确认的触发方式 |
| --- | --- |
| 附近有安全落点 | 短按 Ctrl 下扫帚 |
| 空中，没有安全落点 | 长按 Ctrl 确认后下扫帚 |

这里的安全落点指附近有供玩家站立的方块表面，且下车位置容得下玩家；不能只根据扫帚的着地标志判断。下方由悬浮扫帚提供承托的候选位置仍按空中退出处理，不因此省略长按确认。

长按时长、落点搜索范围和提示形式仍待确定。输入衔接可继续比较松手取消、执行前复查落点，以及要求上车前已按住的 Ctrl 松开后重新操作等细节；这些尚未形成完整规格。

### 优先候选：停稳悬浮与站立承托

维护者指定的优先候选是：**下车后扫帚停稳悬浮并保留实体，玩家站在其碰撞箱上方，由扫帚提供支撑。** 优先级已经确认，具体行为尚未定案或实现。

该候选需要进一步明确停稳与退出的衔接、玩家站立空间、承托面的范围、持续移动输入的处理，以及有安全方块落点时与直接落地的关系。还需验证实体碰撞和多人同步下的稳定性；仅把玩家放到碰撞箱顶部不代表已经能够可靠承托。

长期悬停的条件、扫帚回收方式及其与建造用途的关系仍待讨论。承托候选不自动授予离开扫帚后的坠落免伤。

### 暂缓的高级功能

2026-10-28，维护者决定将以下内容作为后续高级功能方向，**当前先搁置**：

- 缓降方案，包括扫帚缓降、下车后给予玩家缓降，以及保持骑乘直到降落等相关扩展。
- 失效保护，例如资源不足、扫帚损坏或被移除后提供缓降、落地保护或其他救援。

这些内容不列入当前方案收敛的前置条件，尚无实现承诺或排期。此前调研依据保留在研究记录中；主动退出的悬停承托候选与上述高级保护分别维护。

## 其余待决定的问题

| 问题 | 当前边界 |
| --- | --- |
| 能力通过什么载体生效 | 装备、饰品、背包物品、专门能力槽与永久成长都曾被讨论，尚未选定 |
| 两种飞行如何共存 | 是否同时持有、空中切换或互斥尚未决定；操纵候选不决定最终能力系统 |
| 如何获取能力并控制使用成本 | 配方、解锁条件、能源消耗与成长机制尚未定义 |
| 启用与物品回收 | 灵梦式飞行的启停、扫帚上车及物品回收方式仍待决定；扫帚主动退出和暂缓功能以本节前述约定为准 |
| 如何兼容其他能力和工具 | 飞行许可、低速控制与资源消耗应分别明确归属；接口方案见调研，尚未采用额外前置 |
| 哪些状态变化需要处理 | 实现时明确死亡、重连、维度切换、存档与恢复后的行为，避免保留失效权限或重复生成扫帚 |
| 坠落保护的边界 | 创造式飞行资格可能连带影响未起飞时的坠落伤害；是否符合前期能力定位需明确，不能只讨论空中速度 |

这些问题不要求在首次操作原型前全部定案。原型的测试环境、临时规则与观察方法见 [003 原型任务约定](../../work/003-flight-prototype/TASK.md)；临时物品、按键和数值只服务实验，不能自动确定正式系统。
