## 范围与决定来源

维护者要求把本次调研保存到项目文档，推荐方案保持候选，暂不改代码。2026-10-27 的新决定是 Shift 用于低速模式；下降键和 Ctrl 的作用仍需讨论，扫帚的按键转向与视角转向需要详细比较。

2026-10-28，维护者逐步确认统一操纵、两档速度和主动下扫帚方向，并要求以悬停承托为优先候选、暂缓缓降与失效保护。按这些新决定收敛旧的转向和退出选项；具体按键、触发约定、候选优先级与暂缓范围统一维护在飞行设计，不在本任务入口重复规格。

本任务保存源码事实与分析，不实施原型，不调整 Java 源码、资源、构建配置或依赖。本轮交付为文档保存与检查，Git 交付另按明确任务处理。

## 验收条件

1. 调研记录保留参考游戏版本、模组版本、分支或提交，以及固定源码链接；区分源码事实、体验推断和待验证项。
2. 飞行设计准确记录维护者已确认的操纵及退出方向；区分下降键等未定项、悬停承托的优先候选和暂缓的高级功能，不把候选自动视为已接受行为。
3. 初次归档比较扫帚两种转向方式及俯仰控制差别；后续按维护者的新决定收敛为统一操纵，保留旧方案的取舍依据，不再将已经确认的输入语义列为待定。
4. 推荐实现路线和验证顺序标为候选；源码阅读不被写成编译、兼容性或试玩通过。
5. 文档分工清楚，入口与本地链接可解析，改动仅限本任务文档。

## 计划

1. 核对上一阶段已读取的源码、参考版本和本地依赖观察。
2. 将源码证据放入研究记录，将当前约定与操纵取舍放入系统设计。
3. 检查引用、候选状态与修改范围，保存结果。
4. 在后续明确决定形成时更新系统设计、必要的源码补充与阶段记录，保留未定细节，并遵循候选优先级与暂缓范围。
