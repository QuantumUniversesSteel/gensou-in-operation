## 共同操作的临时细则

已确认的键位和方向语义直接遵守飞行设计，不在此复制另一张完整键位表。原型补充以下试用规则：

1. 移动、上升和低速跟随原版移动、跳跃及潜行动作的改键。参考试玩环境使用按住潜行；若使用原版切换潜行，低速跟随其动作状态，不另建一套低速切换设置。
2. 下降使用独立、可改键的动作，默认试用 V，两种飞行共用；C 通过改键进行对比。下扫帚使用另一个独立动作，默认左 Ctrl，不直接把原版疾跑动作当成退出请求。
3. 低速同时降低水平与升降速度，鼠标观察不减速。原版疾跑及双击前进不得在本模组飞行中产生第三档速度。
4. 水平斜向输入不额外提高目标水平速度；相反方向输入相抵，上升与下降同时输入时不产生净升降请求。
5. 无移动输入时保持悬空，已有速度按制动规则收敛。灵梦式侧重停位，扫帚可有少量惯性；低速不能持续滑到难以定位。
6. 保留潜行使用工具所需的语义，单独处理飞行下降和骑乘退出，不能简单清空全部潜行输入。原型先用原版方块交互验证，不据此宣称兼容所有扳手或外部工具。
7. 开启界面或失去窗口焦点后停止接收新的飞行移动请求，并取消未完成的退出确认；恢复后不执行积压的按键。游戏正常暂停与多人世界继续运行须分别观察。

### 初始调参约定

以下是试验起点，可以根据观察调整；修改后记录所用参数和理由。

| 参数 | 拟采用起点 | 判断目的 |
| --- | --- | --- |
| 常速关系 | 灵梦式参考原版非疾跑创造飞行；扫帚水平常速先取其约两倍 | 能辨认建造与跑图的用途差别；实际值由实现标定 |
| 低速倍率 | 各自目标速度的 0.25，水平与升降都应用 | 初步验证靠墙定位及低速降落 |
| 升降速度 | 两种飞行先采用相同的常速升降基准 | 减少切换操作时的高度控制差异 |
| 空中长按 | 初值 0.6 秒；计时口径和低 TPS 下表现须记录 | 减少误触，同时不让主动退出等待过久 |
| 安全落点搜索 | 先限制在当前位置周围水平 2 格、垂直上下 1 格的近邻范围 | 只尝试附近落脚处，不变成远距离传送 |

## 灵梦式飞行的原型行为

测试开关物品右键切换本模组的测试飞行资格。为减少入口复杂度，首次只允许玩家站在有方块支撑的位置、未骑乘时切换；空中使用给出提示，不强制关闭或新增救援。物品是测试开关，资格不依赖物品始终留在某个槽位；这不决定正式能力载体。

| 状态与操作 | 原型预期结果 |
| --- | --- |
| 没有测试资格，使用开关 | 添加本模组的飞行资格来源；保持未起飞，并显示反馈 |
| 有资格但未飞行，双击跳跃 | 进入飞行；具体识别先沿用原版习惯 |
| 正在飞行，再次双击跳跃 | 结束当前飞行，资格暂保留 |
| 飞行中接触地面 | 结束当前飞行，资格暂保留 |
| 在允许的位置再次使用开关 | 撤销本模组测试资格并清理本模组操纵状态 |

初始实现候选采用当前 NeoForge 的创造飞行资格机制，具体 API 在实施时按项目依赖核实。只添加、移除本模组自己的来源，不以恢复旧布尔快照的方式覆盖其他来源。

原版创造式飞行资格可能在未起飞时也影响坠落伤害。原型先接受并记录所选机制的这一副作用，不把它定为正式玩法；测试扫帚承托时必须关闭这项资格，避免掩盖坠落结果。

### 两种飞行的互斥

每名玩家同一时刻只启用一种测试飞行。为避免自动切换造成隐藏状态，灵梦式测试资格未关闭时拒绝上扫帚并提示先关闭；不只检查玩家是否正在飞行。下扫帚不自动开启另一种飞行。正式切换体验后续再设计，不为原型预建通用能力管理框架。

## 扫帚的放置、骑乘与回收

1. 使用测试扫帚物品，在有足够空间的方块表面放置一个停放实体。生存模式成功放置才消耗一个物品，失败不消耗；创造模式按其物品使用习惯处理。
2. 右键无人骑乘的扫帚上车。只有成功建立骑乘关系后才接受控制输入；初始单座，不实现所有权或多人搭乘系统。
3. 骑乘期间按共同操纵移动；接触地面仍保持骑乘，玩家使用退出动作下车。持续站在扫帚顶部与真正骑乘须明确区分。
4. 所有成功的主动退出都让扫帚停稳并保留实体。退出后可以再次右键骑乘；短按地面退出和空中承托的位置差别见下一节。
5. 暂用潜行右键回收无人扫帚：操作玩家须站在安全方块上，且没有玩家站在该扫帚上方受它承托。背包有空间才由服务端移除实体并返还一个物品；否则提示并保持原状。
6. 原型不实现扫帚受击破坏、消耗导致失效或远程召回。管理员移除实体属于调试行为，不承诺为脚下实体被强制删除提供救援。

放置、回收及多人同时交互只能产生一次有效结果。拒绝条件不能先消耗物品或移除实体，再尝试补救。

## 主动下扫帚与承托实验

### 安全落点的范围

在调参约定的有限范围内，寻找有方块支撑、能容纳玩家且没有明显危险的落点。应考虑台阶、半砖及头顶空间；不选取水、岩浆、明显危险表面、世界边界外或未加载区域中的位置，也不允许穿过墙体或天花板到达落点。

优先使用附近合适的落点，具体排序在实现时记录。安全落点必须由服务端在实际退出前复查；扫帚顶部承托不算安全地面落点，不能据此跳过空中长按。

### 输入与状态转换

这里使用逻辑状态描述行为，不要求为每一行建立独立类或通用状态框架。

| 当前情况 / 事件 | 原型临时处理 |
| --- | --- |
| 上车时退出键已经按住 | 等待该键松开后才接受新的退出按下，防止上车即下车 |
| 新按下退出键，当前有安全落点 | 请求短按退出；执行前复查，通过后停稳扫帚并把玩家放到该方块落点 |
| 短按请求执行前，原落点已不可用 | 取消本次退出并提示；不把原短按自动转成延迟执行的退出 |
| 新按下退出键，当前没有安全落点 | 开始空中长按计时，显示进度；此时仍然骑乘并可操纵 |
| 计时中出现安全落点 | 本次请求仍需完成原有长按；松开后重新短按才走短按路径，避免按住时突然下车 |
| 提前松手、打开界面、失焦或骑乘关系改变 | 取消进度；恢复后不沿用旧计时 |
| 长按达到阈值 | 重新判断落点；有安全方块落点则使用它，否则尝试顶部承托；每次按住最多执行一次 |
| 顶部没有足够站立空间 | 保持骑乘，取消此次确认并提示空间不足；不把玩家塞入方块 |

服务端核对请求者确实是当前骑乘者、持续输入和退出条件；不直接接受客户端指定的落点或自报长按完成时间。断开的客户端不能留下仍在计时或推进的输入。

### 停稳悬浮与站立承托

本节实现的是优先候选的实验版本，不把候选提前转为长期设计。

- 无安全方块落点时，先验证扫帚顶部居中位置是否能容纳玩家。确认成功的退出中，扫帚停止推进，水平与垂直剩余速度归零，保持当前位置，再解除骑乘并把玩家放到顶部。
- 有安全方块落点时，玩家直接站到该落点，扫帚同样停稳保留；不要求地面退出也必须站在扫帚上。
- 无人扫帚在原型中持续悬停，不收取资源；不增加超时自动消失。这只是无消耗测试环境下的临时规则，不能据此确定正式停放成本或永久空中平台能力。
- 松开移动键的玩家应能稳定站立、观察和使用物品；扫帚不应因承托接触而持续被挤走。碰撞尺寸应与占位外观可理解地对应，不能仅靠扩大不可见承托面掩盖问题。
- 初次实验保留正常步行输入，不新增自动锁脚。玩家持续按住 W 时会尝试走动；该场景单独评价是否需要输入过渡，不能宣称已防止主动或误操作走离扫帚。
- 走离扫帚后不附加缓降、免伤或自动接回；实体被移除后的救援也不加入本次原型。

如果顶部承托不稳定，应保留复现条件、表现和可行替代判断，报告该验收未通过。可以交付阶段原型与实验结论，但不能通过删除承托要求、禁止所有空中退出或加入已暂缓的保护来宣布完整原型通过。

## 状态保存与异常边界

基础状态清理属于原型正确性，以下规则不提供新的高级救援能力。

| 情形 | 原型临时边界 |
| --- | --- |
| 正常停放、保存和重新载入 | 保存扫帚的实体身份及停放位置；载入后静止悬停，不复制物品或实体 |
| 扫帚区块卸载 | 使用正常实体保存流程，不为测试扫帚强制加载区块；承托只在实体正常加载时讨论 |
| 玩家死亡、退出登录 | 清理本模组测试飞行资格、低速及退出计时；正常仍存在的扫帚解除控制、停稳保留，不再额外生成一份物品 |
| 玩家重连 | 测试资格默认不恢复，不自动恢复骑乘或上次输入；原型不承诺空中重连的救援或安全着陆 |
| 玩家跨维度 | 清理本模组测试飞行状态；扫帚不自动跟随，正常保留在原维度并停稳；不在目标维度复制 |
| 游戏模式切换 | 清理本模组临时控制，尊重原版创造 / 旁观权限；回到生存后重新通过测试入口取得资格 |
| 创造模式或其他来源也提供飞行 | 仅撤销本模组来源；不关闭外部仍有效的权限。外部模组的全面组合测试不在本轮范围 |

地面重连、保存载入及维度往返需要测试。空中重连或强制移除导致的失去支撑可以作为已知限制记录，但不得将重复实体、残留权限或崩溃归为“保护暂缓”而忽略。

## 工程约束与实现准备

现有构建配置为 Minecraft 1.21.1、NeoForge 21.1.264、Java 21；执行命令和完整工具链以工程概览及实际配置为准。原型不更换版本或加载器，不增加 Curios、Flight API 等必需前置；引用现有研究不等于引入被研究项目的依赖或源码。

客户端负责输入、必要的移动响应和显示；服务端负责资格、骑乘关系、物品与实体变更、落点及退出结果。移动预测与同步沿当前版本机制实现，不在此预定未经验证的网络接口。专用服务端不能加载客户端专属类。

不得全局修改其他载具的下车操作或其他来源的飞行速度；本模组控制应有明确生效条件与退出清理。原型资源必须标识测试用途，资源标识及占位来源记录在阶段结果中。

开始实施后先核实基线构建与客户端、独立服务端入口。若遇到既有构建问题，记录事实和修复范围；不能用历史构建产物作为本次验证证据。

| F05 | 测试资格仍在时尝试骑扫帚，关闭后再骑；退出后观察 | 互斥规则和提示一致，不自动用另一种飞行掩盖退出结果 |
| F06 | 放置、上车、地面短按退出、再次上车、回收；背包放满重试 | 成功与失败不吞物品、不复制；回收条件和反馈符合约定 |
| F07 | 在完整方块、半砖、台阶、悬崖边、低顶、隔墙及危险表面附近短按 | 只使用实际合适的近邻落点；不能穿墙、卡头或把悬崖外判为安全 |
| F08 | 高空轻点 Ctrl、长按后提前松手、完成长按 | 轻点和取消不退出；完成确认后执行一次，进度反馈明确 |
| F09 | 按住 Ctrl 上车；确认期间开界面、失焦、移到有落点处或断开连接 | 无立即误下车、旧计时延续或积压请求；断开后扫帚停止接受控制 |
| F10 | 无安全落点且顶部足够宽敞时完成退出，松开移动键观察至少 10 秒 | 玩家由扫帚稳定承托，扫帚停稳，无持续下落、明显抖动或被接触挤走；记录第一与第三人称表现 |
| F11 | 顶部空间不足、持续按 W 下车、主动走离、再次骑乘 | 空间不足时保持骑乘；分别记录持续输入与走离结果，不将它们伪装成自动保护成功 |
| F12 | 玩家站在扫帚上时尝试回收；两名玩家同时上车或回收 | 不移除正在承托玩家的扫帚；每个交互只产生一个服务端结果 |
| F13 | 地面注销重连、死亡、扫帚区块卸载重载、保存重启与维度往返 | 无残留权限、输入或重复实体；停放状态可解释，已知空中恢复限制单独注明 |
| F14 | 切换创造 / 旁观 / 生存；清理本模组资格 | 原版权限不被错误撤销，返回生存后测试状态明确 |
| F15 | 独立服务端连接驾驶者和观察者，复测移动、退出、承托及回收 | 双方所见状态一致，服务端不崩溃，无持续回拉；多人结果不能用单人试玩替代 |
| F16 | 建筑墙面慢速定位、斜向升降、跑图后减速停靠 | 保存可重复路线、使用参数、停止距离及体验反馈，决定是否调整控制或保留承托候选 |

自动化优先覆盖能独立验证的状态变化：短按与长按分支、取消与重复请求、落点拒绝时不部分退出、物品和实体只变更一次、权限来源清理。落点形状与实体承托可按需要用集成或 GameTest 验证；不强制为每个简单访问器补测试，也不把自动化当作手感证据。

构建使用仓库 Gradle Wrapper；按实际新增测试运行相应检查。客户端和独立服务端的人工步骤及结果分别记录。只有服务端启动成功仍不足以宣称 F15 通过；没有第二客户端、试玩条件或其他验证条件时，保留未验证项和原因，不能写成全面通过。

## 实施顺序与完成标准

1. **准备工程基线与测试入口**：核实版本、构建和运行，添加临时入口与可辨认的资源，记录参数来源。
2. **完成灵梦式飞行**：验证共同操作、资格与启停、低速交互和清理，形成可以单独体验的阶段结果。
3. **完成扫帚基本循环**：放置、骑乘、移动、地面退出、再次骑乘、回收，先保证实体与物品结果一致。
4. **完成空中退出实验**：接入长按、落点复查和停稳承托；记录成功条件与失败场景，不引入暂缓功能弥补实验失败。
5. **验证并整理结论**：执行适用自动化、独立服务端和双客户端检查，收集手感反馈，更新实际形成的长期结论。

每一步完成才记录相应结果。完整原型交付需要已约定的基础功能与关键验收通过，并明确手感及承托实验结论；有未通过或未验证项时可交付阶段成果，但任务状态必须反映实际限制。试验否定某个候选时保留证据，后续范围修订不能通过静默删除验收项完成。
