## 2026-10-29：测试飞行资格的生命周期

### 实现与边界

- 为现有资格开关补齐服务端生命周期处理：登录、退出、重生、完成跨维度时移除自身来源；玩家 tick 检查实际死亡和游戏模式变化，服务器停止时清空会话记录。保留原有物品使用条件，没有加入低速、下降、扫帚或救援功能。
- 授予时在内存记录 UUID 与实际游戏模式，用于识别会话变化；不保存到玩家 NBT。模式切换前事件只检查已经生效的实际变化，玩家 tick 继续核对，避免取消请求误撤销，同时覆盖同 tick 模式往返。
- 撤销只移除自身修饰符；综合资格消失且仍在飞行时才关闭飞行状态并发送原版能力包。属性变化使用既有 NeoForge 同步，不增加自定义网络协议。现行结构与约定的主要维护位置是 [飞行工程实现](../../docs/engineering/flight.md)。
- 增加仅 GameTest 运行加载的测试模组与独立源集，使用本项目生成的空测试结构；测试世界、日志和玩家数据隔离在 `build/gametest/`。正式客户端和模组 JAR 不包含测试模组。CI 配置增加独立的 GameTest 步骤，但本轮未推送，尚未取得远端 CI 结果。

### 权限机制与改键的源码评估

本次委派 `mod_researcher` 做有界只读研究，核对实际 Minecraft 1.21.1、NeoForge 21.1.264 依赖源码与官方资料。结论是**继续使用 `CREATIVE_FLIGHT` 作为灵梦式资格层，并独立处理操纵与状态恢复**；具体输入钩子和存储结构仍是候选，没有新增依赖、Mixin、按键或网络协议。

| 核对位置 | 源码事实与本项目影响 |
| --- | --- |
| `IPlayerExtension#mayFly`、`ServerGamePacketListenerImpl#handlePlayerAbilities` | 综合原版能力与属性判断资格，服务端据此接受飞行状态请求；资格机制不规定物理键位 |
| `LocalPlayer#aiStep`、`isShiftKeyDown`、`sendPosition` | 默认升降分别读取跳跃和潜行输入；同一潜行输入也参与交互语义和服务端潜行状态上报，不能为阻止下降直接清空 |
| `MovementInputUpdateEvent` | 在客户端读取移动输入后触发，可采集或调整输入，但不会自动替换后续创造飞行升降分支 |
| `Player#getFlyingSpeed` | 原版飞行疾跑有额外速度倍率；只是不新增 Ctrl 加速绑定，仍不能消除它及双击前进触发的第三档 |

| `ServerPlayerGameMode#setGameModeForPlayer`、`GameType#updatePlayerAbilities` | NeoForge 服务端模式更新会保留先前 `flying`；旁观还会强制飞行。客户端模式更新仍有覆盖能力的路径，需处理同步时序及旁观前状态 |
| `ServerPlayer#changeDimension`、`doTick` | 常规跨维度复用服务端玩家并同步能力；资格恢复过晚则可能被“正在飞行但无有效资格”的检查停飞。当前项目的跨维度事件会主动撤销自身来源 |
| `ServerGamePacketListenerImpl#handleClientCommand`、`PlayerList#respawn`、`ServerPlayer#restoreFrom` | 末地出口返回会创建新玩家，`Clone#isWasDeath()` 为假、`PlayerRespawnEvent#isEndConquered()` 为真；不能把所有 respawn 事件都当作死亡清除，单纯跨维度传送不覆盖此路径 |
