# 状态延续：真实客户端复测

适用阶段：2026-11-04 的灵梦式飞行状态延续实现。对应 [任务](TASK.md) 的 F04、F13、F14 及本阶段的双客户端观察；不包含尚未实现的改键、扫帚和承托。执行情况与环境记录在 [RESULT.md](RESULT.md)，本文只维护可重复步骤。

本页保留该阶段已执行的完整复测资料。后续回归按 [验证规则](../../AGENTS.md#模组工程与验证) 选取受影响场景。

## 准备与辨认状态

1. 停止旧的开发客户端、服务端，在 IDEA 重新加载 Gradle 工程后重新启动，确保本轮 Mixin 配置和类已加载。启动入口仍为 `runClient` / `runServer`；命令见 [工程概览](../../docs/engineering/README.md#开发入口)。
2. 使用允许指令的独立测试存档；第一轮只加载本项目及 NeoForge。先单机检查，再连接独立服务端重复关键项目。以下命令在玩家聊天栏执行，服务端控制台的 `stop` 不加斜杠。
3. 取得测试开关：`/give @s gensou_in_operation:flight_test_switch`，切到 `/gamemode survival`。在完整方块上、未骑乘时右键开关。当前仍是双击空格启停、空格上升、Shift 下降，V 和 Shift 低速尚未接入。
4. 准备下面三种起点；每项前重新设置，不依赖上一项留下的状态。首次加载旧存档不会凭空补回过去未保存的测试资格，需要重新开启一次。

| 起点 | 设置方法 | 本来源 / 实际飞行 |
| --- | --- | --- |
| A：关闭 | 在地面关闭测试资格 | 不存在 / `0b` |
| B：已开启、未起飞 | 地面开启，不双击空格 | `1.0` / `0b` |
| C：正在飞行 | 开启后双击空格，升至离地约 3–5 格，松开移动键 | `1.0` / `1b` |

分别查询资格来源和实际飞行位：

```mcfunction
/attribute @s neoforge:creative_flight modifier value get gensou_in_operation:reimu_test_flight
/data get entity @s abilities.flying
```

关闭时第一条提示该修饰符不存在是正常结果。总属性值或创造模式能飞，不足以证明本模组资格存在。着地会按原版停止实际飞行，但应保留资格；观察转换导致的异常下坠时，应让目标位置也悬空，避免混淆正常着地。

## 单机先检查

| 项目 | 具体操作 | 预期结果 |
| --- | --- | --- |
| 开关与正常停飞 | 主手、副手分别开启/关闭；开启后双击空格起飞、主动停飞、再次起飞并落地 | 反馈各一次；主动停飞和落地只改变飞行位；地面关闭才撤销资格，箱子仍能正常交互 |
| 普通模式 | 在 B、C 下依次 `/gamemode adventure` → `creative` → `survival`；C 全程保持离地 | 每一步本来源仍存在；B 不自动起飞，C 保持飞行。另从 A 重复，模式变化不能创建本来源 |
| 旁观往返 | B 下进入 `/gamemode spectator`，在地面上方约 3 格退出到 survival；再从 C 重复；另测退出到 creative | 旁观期间能自由飞行；B 离开后未起飞、会正常落下，C 离开后仍飞行；资格均保留。退出到 creative 也恢复进入前的飞行位 |
| 单机保存退出 | A、B、C 分别“保存并退出到标题画面”，重新进入；再在 B→旁观、C→旁观期间保存退出，重进后离开旁观 | A 不获资格；B 不自动起飞；C 空中恢复并能立即移动；旁观重进后仍按进入前的 B/C 状态恢复 |
| 死亡 | 从 B、C 分别 `/kill @s`，点重生；另一次死亡后停在死亡界面直接退出，再进世界、重生 | 本来源消失，生存模式不能再双击起飞；重新右键可开启。不要把创造或外部来源仍能飞误判为本来源残留 |

## 独立服务端重点检查

启动已有开发独立服务端，客户端连接 `localhost`（本机默认端口时）。使用同一个玩家身份重连；不要用每次随机用户名的新玩家代替重连。

| 项目 | 具体操作 | 预期结果 |
| --- | --- | --- |
| 断线重连 | A、B、C 分别退出到多人列表，再连接；C 先松开操作键 | 与退出前状态一致；C 无需重新双击起飞，不持续下坠、回拉或保持旧的移动操作 |
| 服务器正常重启 | 在上述各起点由服务端控制台执行 `stop`，等进程保存并完全退出，再启动 `runServer`，同一玩家连接 | A/B/C 分别恢复；需观察完整进程退出与重启，`/reload` 不能替代此项 |
| 旁观期间重连、重启 | B→旁观后分别做断线重连、正常停服重启，再切回 survival；C→旁观同样重复 | 旁观时原版飞行正常，离开后分别恢复 B 或 C；不把旁观强制飞行永久记成已起飞 |
| 维度往返 | 用下方步骤在主世界与下界间传送；分别从 A/B/C 测试，随后用实际下界传送门再往返一次 | 资格不变；C 传送到悬空目标仍保持飞行。B/A 在悬空目标正常下落，不能因传送自动起飞 |
| 末地出口 | 使用专用测试世界中已激活的末地返回门；进入前设为 B 或 C，从实际返回门经过终末之诗/返回流程 | 返回后资格保留。C 不应因非死亡重建丢失飞行；若出生点立即接触地面，允许正常停飞，需与转换丢失区分。仅用跨维度 tp 不覆盖这一流程 |
| 死亡边界 | 重复单机死亡项目；再在死亡界面时执行正常 `stop`，重启并重生 | 死亡资格不会因退出过快或加载旧玩家位而复活 |
| 第二客户端 | 观察者在同一维度观看 C 起飞、模式切换、重连及返回；测试者进入/离开旁观，观察者保持非旁观 | 飞行位置无持续抖动、回拉或异常下坠；进入旁观隐藏、离开恢复可见，观察者看到的行为与驾驶者一致 |

维度测试可在测试世界先准备两处平台。下列指令会更改指定小范围方块，仅用于该测试世界：

```mcfunction
/execute in minecraft:overworld run fill -2 200 -2 2 200 2 minecraft:stone
/execute in minecraft:the_nether run fill -2 200 -2 2 200 2 minecraft:stone
/execute in minecraft:overworld run tp @s 0.5 201 0.5
```

在主世界平台设置起点；C 双击起飞后再传送。依次执行：

```mcfunction
/execute in minecraft:the_nether run tp @s 0.5 204 0.5
/execute in minecraft:overworld run tp @s 0.5 204 0.5
```

每次等待区块显示及约 5 秒，查询来源和飞行位并尝试移动。B/A 会落到平台，是预期结果；C 应一直悬停。实际传送门复测时同样留意是否已经碰地。

## 外部来源共存及记录

先在生存模式地面给自己一个独立的模拟来源，再开启本模组资格：

```mcfunction
/attribute @s neoforge:creative_flight modifier add flight_test_other:permission 1 add_value
```

起飞、落地并关闭本模组资格。查询本来源应不存在，但外部来源仍应存在，仍能双击起飞；重连后再次检查。结束后移除模拟来源：

```mcfunction
/attribute @s neoforge:creative_flight modifier remove flight_test_other:permission
```

这验证独立属性来源，不代表所有第三方模组兼容。服务器实际启用 `force-gamemode` 时，可另做普通存档→强制旁观登录→退出，以及旁观存档→强制生存登录；须保留原本的 B/C 状态。自动化已模拟该登录阶段，真实服务器配置联动尚未实测，常规复测无需为此改服务器配置。
